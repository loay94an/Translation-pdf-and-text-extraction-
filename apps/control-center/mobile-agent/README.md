# خادم الطرفية المحلية لأندرويد (Termux)

هذا الخادم المرافق يتيح لواجهة `/mobile-terminal.html` إرسال أوامر إلى Termux على الهاتف نفسه.

## المتطلبات
- Android مع تطبيق Termux حديث من مصدر موثوق.
- اتصال إنترنت أول مرة لتنزيل Node.js ولتحميل واجهة الويب.
- فتح الموقع المنشور عبر HTTPS.

## التشغيل
انسخ مجلد `mobile-agent` إلى الهاتف أو نزّل ملفات المشروع، ثم في Termux:

```bash
pkg update -y
pkg install -y nodejs-lts
mkdir -p ~/workspace
cd /path/to/mobile-agent
bash start.sh
```

عند التشغيل سيطبع الخادم رمزًا عشوائيًا. افتح الموقع ثم صفحة **الطرفية المحلية**، أدخل الرمز واضغط اتصال. لا ترسل الرمز لأي شخص.

يمكن ضبط مجلد العمل قبل التشغيل:

```bash
LOCAL_AGENT_WORKSPACE="$HOME/projects" node agent.mjs
```

المنفذ الافتراضي 8765 ويمكن تغييره عبر `LOCAL_AGENT_PORT`.

## الحدود والحماية
- يستمع الخادم إلى `127.0.0.1` فقط؛ لا تستخدم نفقًا عامًا ولا تغيّر عنوان الاستماع إلى `0.0.0.0`.
- كل طلب يحتاج Bearer token عشوائي محفوظ في `~/.config/mobile-terminal-bridge/token` بصلاحية قراءة للمالك فقط.
- تغيير المجلد مقيد داخل مجلد مساحة العمل، لكن الأوامر نفسها تعمل بصلاحيات مستخدم Termux ويمكنها الوصول إلى ملفات أخرى إذا كتبت مسارات مطلقة. لا تشغّل أوامر غير موثوقة.
- مهلة الأمر دقيقتان وحد الخرج 128KB. هذا منفذ أوامر قصير المدى وليس طرفية TTY كاملة؛ الأوامر التفاعلية مثل `nano` و`top` والجلسات طويلة التشغيل غير مدعومة.
- لا يعمل الخادم المحلي إذا أُغلق Termux أو أوقف Android عمليته في الخلفية.
- قد يطلب Chrome إذن الوصول إلى الشبكة المحلية عند الاتصال بـ localhost. توافق هذا الاتصال يعتمد على إصدار Android والمتصفح وسياسات الوصول المحلي.
- الواجهة PWA قابلة للتثبيت وتخزن ملفاتها الأساسية فقط؛ تنفيذ الأوامر يتطلب أن يكون الخادم المحلي قيد التشغيل.


## تجهيز محركات استخراج المراجع

اقرأ الدليل العربي الكامل في `EXTRACTION-SETUP-AR.md`، وابدأ من `QUICKSTART-AR.md`. لتثبيت أدوات Termux:
```bash
bash install-termux.sh
bash doctor.sh
```

الأدوات المطلوبة لمسار الاستخراج الحالي:
- Poppler: `pdftotext`, `pdfimages`, `pdftoppm`.
- Tesseract مع `ara` و`eng` (وتضاف اللغات الأخرى عند الحاجة).
- Python 3 لتشغيل محركات الاستخراج الموجودة في جذر المستودع داخل `extraction/`، ومنها `extraction/scripts/model_enrich.py` لاستخراج البيانات المنظمة بالنموذج.

## مهام الخلفية والنماذج المحلية

- `POST /api/jobs` يبدأ أمرًا طويلًا في الخلفية ويعيد معرّف المهمة.
- `GET /api/jobs/:id` يعيد الحالة وآخر 128KB من المخرجات.
- الحد الأعلى للمهمة 6 ساعات. سجلاتها تكتب في `~/.config/mobile-terminal-bridge/jobs/`.
- حالة المهمة الحية موجودة في ذاكرة الخادم؛ إذا أُعيد تشغيل Termux لا تستمر جلسة المتابعة، لكن ملفات السجل ومخرجات الاستخراج تبقى على القرص.
- `GET /api/models` يفحص واجهة OpenAI-compatible الافتراضية `http://127.0.0.1:8080/v1/models`. غيّرها عبر `LOCAL_MODEL_BASE_URL`، ويمكن ضبط `LOCAL_MODEL_API_KEY` للخوادم التي تتطلب مفتاحًا.
- واجهة الموقع توفر أزرار تشغيل استخراج النصوص وOCR واستخراج البيانات المنظمة بالنموذج في الخلفية، إضافة إلى فحص النموذج المحلي.

## ربط النموذج المحلي وChatGPT

- GET /api/providers يعرض النموذج المحلي فقط.
- POST /api/chat يرسل النصوص إلى خادم النموذج المحلي فقط.
- لا يخزن هذا الجسر مفاتيح API سحابية ولا يقدم وسيطًا عامًا لخدمات الذكاء الاصطناعي.
- ربط ChatGPT يكون من تطبيق Android الأصلي عبر Sign in with ChatGPT الرسمي (OAuth/PKCE)، وليس عبر جلسة Chrome أو كوكيز تطبيق ChatGPT. تفاصيل التصميم في دليل CHROME-ANDROID-INTEGRATION-AR.md.
- Chrome هو المتصفح الأساسي المثبت على الهاتف؛ يتعامل معه التطبيق عبر Android Intents وCustom Tabs ومشاركة المحتوى، ولا ينشئ متصفحًا بديلًا.

## السماح للموقع بالاتصال المحلي

يجب ضبط `LOCAL_AGENT_ALLOWED_ORIGINS` على أصل الموقع المنشور بالضبط، مثل `https://your-domain.example`، قبل بدء الخادم. يمكن إضافة أكثر من أصل بفصلها بفواصل. لا تستخدم النجمة. أمثلة:
```bash
LOCAL_AGENT_ALLOWED_ORIGINS="https://your-domain.example" bash start.sh
```
إذا كان المتصفح يفتح الموقع من عنوان مختلف، أضف ذلك الأصل صراحة. الطلبات التي لا تحمل Origin (مثل curl من Termux) تظل متاحة مع رمز الاتصال.


### تشغيل مرحلة البيانات المنظمة
بعد انتهاء OCR، اضغط زر **استخراج البيانات بالنموذج**. هذه المرحلة تستخدم `$EXTRACTION_ROOT/scripts/model_enrich.py` من المستودع الموحد، وتكتب نتائج JSONL في `assets/fashion-model-library/extracted-knowledge/structured-pages/`. ابدأ بعينة صغيرة من الطرفية قبل تشغيل كل الكتب:
```bash
python "$EXTRACTION_ROOT/scripts/model_enrich.py" --book-id BOOK_ID --max-pages 2
```
متغيرات النموذج:
- `LOCAL_MODEL_BASE_URL`: افتراضيًا `http://127.0.0.1:8080/v1`.
- `LOCAL_MODEL_NAME`: افتراضيًا `qwen-local`.
- `LOCAL_MODEL_API_KEY`: اختياري، يبقى في بيئة Termux ولا يوضع في الصفحة.

النموذج الصغير قد يخطئ في الجداول؛ النتائج غير متحققة. لا يتضمن هذا المسار حتى الآن تحليلًا بصريًا للرسومات أو استخراج هندسة قطع الباترون.

## تطبيق Android الأصلي

يوجد الآن مشروع Kotlin/Jetpack Compose أولي في `android-app/`. افتح هذا المجلد في Android Studio أو استخدم سير عمل GitHub Actions لبناء APK تجريبي.

التطبيق يفتح الروابط في Chrome، يستقبل المشاركات والملفات، يستخرج نص PDF النصي، ويحفظ نسخة من الملف في `Download/ControlCenter` لتكون متاحة لـTermux بعد تنفيذ `termux-setup-storage`. كما يتصل بخادم هذا المجلد على `127.0.0.1:8765` ويستطيع إرسال النص إلى النموذج المحلي وتنفيذ أوامر Termux التي يكتبها المستخدم.

للتشغيل:
1. ابدأ خادم Termux عبر `bash start.sh`.
2. انسخ رمز الاتصال الظاهر في Termux إلى التطبيق مرة واحدة، ثم اختبر الاتصال.
3. تأكد من تشغيل خادم النموذج المحلي على المنفذ 8080.
4. شارك ملف PDF من Chrome أو أي تطبيق إلى «مركز التحكم»، ثم اختر تحليل النموذج المحلي أو استخدم مسار OCR في Termux.

هذه نسخة تطويرية وليست إصدارًا نهائيًا: لا يوجد بعد تكامل SIWC الفعلي، ولا TTY تفاعلي، ولا APK موقع للإصدار النهائي. لا تنفذ أوامر غير موثوقة لأن أوامر الجسر تعمل بصلاحيات مستخدم Termux.

### بدء خادم Termux تلقائيًا عند تشغيل الهاتف

بعد تثبيت تطبيق Termux:Boot من مصدر Termux نفسه وفتحه مرة واحدة، شغّل:
```bash
bash install-boot-start.sh
```
يضيف هذا سكربتًا إلى `~/.termux/boot/` ليبدأ الجسر تلقائيًا بعد الإقلاع. اضبط البطارية على عدم تقييد Termux وTermux:Boot. سجل التشغيل يحتوي رمز الاتصال، لذلك يبقى داخل مجلد Termux الخاص ولا تتم مشاركته.


## استخراج PDF متعدد المراحل ومتابعة المهام

يدعم محرك `extraction/scripts/extract_single_pdf.py` الاستراتيجيات التالية:
- `--ocr-mode none`: استخراج النص الأصلي دون OCR.
- `--ocr-mode empty`: OCR للصفحات التي لا تحتوي نصًا.
- `--ocr-mode weak`: إعادة OCR للصفحات التي يقل نصها عن `--min-text-chars` (افتراضي 40)، واستبدال النص فقط إذا كانت نتيجة OCR أطول.
- `--ocr-mode all`: OCR لكل الصفحات ومقارنة النتيجة بالنص الأصلي.
- `--ocr-lang ara+eng`, `--dpi 220` (من 100 إلى 400)، و`--psm 3` لضبط Tesseract.

يبث المحرك أحداث تقدم منظمة تبدأ بالبادئة `@@PROGRESS`، وتتضمن المرحلة والصفحة الحالية والعدد المكتمل والإجمالي والنسبة المئوية. يلتقط الجسر هذه الأحداث ويعرض تقدمًا محسوبًا من الصفحات، لا نسبة زمنية تقديرية.

مثال:
```bash
python "$EXTRACTION_ROOT/scripts/extract_single_pdf.py" book.pdf --output-dir "$PWD/extracted-pdf" --prefix book --ocr-mode weak --min-text-chars 40 --ocr-lang ara+eng --dpi 300
```

### مدير المهام
- `POST /api/jobs`: يبدأ مهمة خلفية.
- `GET /api/jobs`: يعرض آخر 100 مهمة.
- `GET /api/jobs/:id`: يعرض الحالة والمخرجات والتقدم.
- `POST /api/jobs/:id/cancel`: يطلب إيقاف المهمة.
- `POST /api/jobs/:id/retry`: يعيد تشغيل أمر مهمة فاشلة أو منقطعة كمعرّف مهمة جديد.

تُحفظ بيانات المهام وسجلاتها في `~/.config/mobile-terminal-bridge/jobs/` بصلاحيات خاصة. عند إعادة تشغيل الجسر تتحول المهمة التي كانت تعمل إلى `interrupted` ولا يُدّعى أنها استؤنفت؛ يمكن إعادة تشغيلها من البداية. ملفات الإخراج الجزئية تبقى للمراجعة، لكن الاستئناف من منتصف الصفحة يحتاج checkpoint منفصلًا ولم يُفعّل بعد.

## استخراج ملف PDF صفحة بصفحة

تضيف صفحة **الطرفية المحلية** مسارًا مستقلًا لملف PDF واحد. أدخل مسار الملف، ثم شغّل الاستخراج. السكربت:

`$EXTRACTION_ROOT/scripts/extract_single_pdf.py`

ينشئ داخل `extracted-pdf/`:
- `extracted.jsonl`: سجل مستقل لكل صفحة مع رقم الصفحة والنص.
- `extracted.txt`: ملف نصي واحد مع فواصل وعناوين صفحات.
- `extracted.html`: صفحة HTML عربية RTL، وكل صفحة داخل قسم مستقل.
- `extracted_page_0001.txt` وما بعدها: ملف TXT منفصل لكل صفحة.
- `extraction-report.json`: عدد الصفحات والفارغة ومسارات المخرجات.

بعد انتهاء المهمة اضغط **عرض الصفحات** للتنقل بين الصفحات، ثم استخدم أزرار نسخ الصفحة أو نسخ النص الكامل أو تصدير TXT/HTML. المعاينة تقرأ JSONL من داخل مساحة العمل فقط، بحد أقصى 8MB و2500 صفحة. يمكن تفعيل خيار OCR التلقائي للصفحات الفارغة؛ يستخدم Poppler لتحويل الصفحة إلى صورة ثم Tesseract باللغة العربية والإنجليزية. تأكد من تثبيت بيانات اللغة العربية في Tesseract. نتائج OCR آلية وتحتاج مراجعة، خصوصًا الجداول والأرقام.

مثال من Termux:

```bash
python "$EXTRACTION_ROOT/scripts/extract_single_pdf.py" "$HOME/storage/downloads/ControlCenter/book.pdf" --output-dir "$HOME/workspace/extracted-pdf" --prefix book --ocr-empty-pages
```

## اختيار النموذج المحلي والمحادثة

تقرأ الواجهة النماذج من `GET /api/models` وتعرض معرفاتها للاختيار. المحادثة ترسل الرسائل إلى `POST /api/chat` مع النموذج المختار، وتظل على الخادم المحلي المحدد بواسطة `LOCAL_MODEL_BASE_URL`. لا تنفذ المحادثة أوامر shell تلقائيًا؛ راجع الأوامر قبل نسخها إلى الطرفية.

لتغيير خادم النموذج، أوقف الجسر ثم شغّله بمتغيرات البيئة المناسبة، مثل:

```bash
LOCAL_MODEL_BASE_URL="http://127.0.0.1:8080/v1" LOCAL_MODEL_NAME="qwen-local" bash start.sh
```

## أين يفيد Google؟

Google Gemini خيار سحابي إضافي وليس شرطًا للاستخراج. قد يفيد عند الحاجة إلى فهم بصري للرسومات والجداول المعقدة أو مراجعة صفحات لا يستطيع OCR تفسيرها أو تحليل مستند طويل بسياق أكبر. أما استخراج النص الأساسي وتقسيم الصفحات فيعمل محليًا عبر Poppler، وOCR عبر Tesseract، والتحليل النصي عبر النموذج المحلي. Gemini يتطلب الإنترنت واعتمادًا سحابيًا ومفتاحًا محفوظًا على الخادم؛ الواجهة الحالية لا تتصل به بعد، ولا ينبغي وضع أي مفتاح في HTML أو مستودع GitHub.


## لوحة العمل الاحترافية

افتح `/studio.html` من الموقع المنشور أو محليًا. تتضمن اللوحة أقسامًا مستقلة:
- **نظرة عامة:** حالة الجسر والمهام ومؤشر سير العمل.
- **إدارة PDF:** مسار الملف، مجلد العمل، بادئة المخرجات، OCR الاختياري، اللغة، DPI، متابعة المهمة، معاينة الصفحات ونسخها وتصديرها.
- **إعدادات OCR:** ضبط اللغة والدقة وتطبيقها على المهمة التالية.
- **النماذج والمحادثة:** فحص النماذج المحلية، ضبط الحرارة والحد الأقصى للتوليد، وإرفاق صفحة PDF بالسياق.
- **ربط المتصفح:** فتح ChatGPT أو أي نموذج في Chrome، ثم استيراد النص الذي يشاركه المستخدم إلى سياق النموذج المحلي.
- **الطرفية والمهام:** مراجعة الأمر قبل تنفيذه يدويًا ومشاهدة المخرجات.
- **الإعدادات والتعليمات:** حفظ عنوان الجسر ورمزه محليًا وشرح التشغيل.

### ترجمة النصوص المستخرجة

من لوحة العمل افتح قسم **ترجمة النصوص** بعد اكتمال الاستخراج:
- حدد ملف JSONL الذي أنشأه استخراج PDF، وملف PDF الأصلي عند الرغبة في إرفاق الصور.
- لغة المصدر: تلقائي لكل صفحة أو اختيار يدوي (العربية، الإنجليزية، الفرنسية، الألمانية، التركية، الإيطالية، الإسبانية، الروسية، الصينية، اليابانية، الفارسية، الأردية). الاكتشاف التلقائي يستخدم `langdetect` إن كانت مثبتة؛ وإلا يحدد العربية من حروفها ويترك اللغات اللاتينية للنموذج كي يكتشفها ضمن تعليمات الترجمة.
- حدد لغة الهدف والنموذج المحلي ودرجة الإبداع وحد التوليد.
- HTML: النص الأصلي والترجمة معًا، أو الترجمة فقط، أو النص الأصلي فقط.
- الصور: لا صور، أو صورة الصفحة كاملة (Poppler/`pdftoppm`)، أو الصور المضمنة داخل PDF (يتطلب PyMuPDF).
- تبدأ الترجمة كوظيفة خلفية عبر مدير مهام Termux، مع تقدم صفحة بصفحة وإمكانية الإيقاف. يلزم تشغيل خادم النموذج المحلي المتوافق على العنوان المحدد في `LOCAL_MODEL_BASE_URL`.

الأوامر المساعدة في Termux:
```bash
pip install langdetect pymupdf
python -m py_compile "$EXTRACTION_ROOT/scripts/translate_extracted_pages.py"
```
PyMuPDF اختياري ولا يلزم عند اختيار صورة الصفحة كاملة أو عدم إرفاق الصور. لا يرسل المحرك النص إلى خدمة ترجمة سحابية؛ يستخدم عنوان خادم النموذج المحلي.

المخرجات في مجلد `translated-pdf` داخل مساحة العمل: `*_translated.jsonl` و`*_translated.txt` و`*_translated.html` و`*_translation-report.json`، إضافة إلى مجلد الصور عند تفعيلها. تُضمّن الصور داخل ملف HTML نفسه بصيغة data URI ليبقى الملف مستقلًا عند نقله أو مشاركته؛ قد يصبح حجم HTML كبيرًا عند اختيار صور الصفحات كاملة.

## الربط بين المتصفح والنموذج المحلي

النسخة الحالية تستخدم مشاركة صريحة: انسخ الرد من Chrome أو استخدم مشاركة Android إلى التطبيق، ثم ألصقه في قسم ربط المتصفح. يمكن للنموذج المحلي تحليل هذا المحتوى واقتراح خطوات أو أوامر، لكن لا يقرأ الموقع جلسة المتصفح أو ملفات تعريف الارتباط ولا يتحكم بها. الربط التلقائي الكامل يتطلب إضافة Chrome/متصفح بصلاحيات واضحة يثبتها المستخدم أو تكاملًا رسميًا يدعم OAuth/API. لا ينبغي استخراج جلسات تسجيل الدخول أو إعادة استخدام كوكيز ChatGPT.

### حدود مؤشرات التقدم

مؤشر المهمة يعرض حالة التنفيذ ويستخدم نسبة تقريبية أثناء العمل؛ لا يدّعي نسبة صفحات دقيقة لأن محرك الاستخراج الحالي لا يرسل أحداث تقدم لكل صفحة. يمكن تطوير ذلك لاحقًا بإضافة سجل أحداث لكل صفحة وعدّاد completed/failed/total.

# محركات الذكاء الاصطناعي في مركز التحكم

## النموذج المحلي

يستخدم الجسر المحلي POST /api/chat مع خادم متوافق مع OpenAI محليًا، افتراضيًا:
http://127.0.0.1:8080/v1

متغيرات الإعداد:
- LOCAL_MODEL_BASE_URL: عنوان خادم النموذج.
- LOCAL_MODEL_NAME: اسم النموذج، افتراضيًا qwen-local.
- LOCAL_MODEL_API_KEY: اختياري للخادم المحلي فقط.

## ChatGPT دون مفتاح API

لا يمر اتصال ChatGPT عبر /api/chat ولا عبر متصفح Chrome. يُنفّذ في تطبيق Android الأصلي باستخدام مسار Sign in with ChatGPT الرسمي:
- OAuth Authorization Code مع PKCE ومتصفح النظام.
- موافقة المستخدم والتحقق من أهلية خطة ChatGPT.
- تخزين الرموز مشفرة بمفتاح Android Keystore.
- اكتشاف النماذج المتاحة وبث الاستجابات عبر واجهات SIWC الرسمية.
- لا قراءة لمحادثات ChatGPT أو ذاكرته، ولا استخراج لكوكيز Chrome أو جلسة تطبيق ChatGPT.
- لا تحويل الاشتراك إلى API عام أو خدمة لطلبات مستخدمين آخرين.

يجب التحقق من توافق SDK الرسمي وترخيصه ومتطلبات Node/Android قبل تضمينه في التطبيق. لا تعتبر هذه المرحلة منفذة بمجرد وجود هذا الدليل.

## لماذا لا نستخدم Chrome لاستخراج جلسة ChatGPT؟

Chrome هو المتصفح الأساسي لتصفح الويب، لكنه ليس قناة API. يفتح التطبيق المواقع عبر Android Custom Tabs أو Intent، ويستقبل الصفحات والنصوص التي يشاركها المستخدم عبر Android Sharesheet. لا يقرأ التطبيق تبويبات Chrome أو ملفات تعريف الارتباط أو كلمات المرور.

## القيود الحالية

- خادم Termux الحالي يدعم النموذج المحلي فقط.
- لا يوجد حتى الآن تنفيذ Android أصلي لـ SIWC أو Chrome intents في هذا الفرع؛ هذه وثيقة تصميم تمهيدية.
- أوامر الطرفية تعمل بصلاحيات مستخدم Termux، وليست صندوقًا آمنًا معزولًا؛ لا تنفذ تعليمات غير موثوقة تلقائيًا.

# تكامل Chrome وAndroid وChatGPT — التصميم المعتمد

## الهدف

يكون تطبيق Android مركز تحكم ينسق بين:
1. Google Chrome المثبت أصلًا على الجهاز، بوصفه المتصفح الأساسي.
2. ChatGPT عبر تسجيل الدخول الرسمي Sign in with ChatGPT (SIWC)، دون مفتاح API تقليدي للحساب المؤهل.
3. نموذج محلي عبر llama.cpp وخادم OpenAI-compatible محلي.
4. Termux/Linux لتشغيل OCR واستخراج الكتب وإدارة الملفات.
5. تطبيقات Android الأخرى عبر آليات المشاركة واختيار الملفات المصرح بها.

لا ننشئ متصفحًا كاملًا بديلًا، ولا نعتمد على استخراج جلسات Chrome أو ChatGPT.

## تكامل Chrome

### فتح المواقع
- فتح الروابط في Chrome المثبت عبر Android ACTION_VIEW مع رابط HTTPS.
- عند الحاجة إلى تجربة تصفح ضمن سياق التطبيق، استخدام AndroidX Browser Custom Tabs؛ هذه واجهة Chrome أو المتصفح الافتراضي وليست WebView لنسخ المتصفح.
- يمكن تحديد حزمة Chrome com.android.chrome عند توفرها، مع fallback إلى ACTION_VIEW إذا لم يكن Chrome مثبتًا أو معطلًا.
- لا يقرأ التطبيق سجل التصفح أو التبويبات أو كلمات المرور أو Cookies.

### استقبال محتوى من Chrome والتطبيقات
تسجيل Activity لاستقبال Android Intents:
- ACTION_SEND لنصوص وروابط text/plain.
- ACTION_SEND وACTION_SEND_MULTIPLE للملفات مع MIME types المناسبة.
- ACTION_VIEW للروابط عند اختيار التطبيق كمستقبل.
- استخدام ContentResolver لقراءة URI الممنوح فقط، ونسخ الملف إلى مساحة عمل التطبيق بعد موافقة المستخدم.
- دعم Android Sharesheet كمسار أساسي؛ لا نفترض إمكانية قراءة محتوى الصفحة كاملة من URL بسبب تسجيل الدخول أو CORS أو الحماية.

### إعادة النتيجة إلى Chrome أو تطبيق آخر
- توفير ACTION_SEND لإعادة النص أو الملف إلى تطبيق يختاره المستخدم.
- نسخ النتيجة إلى الحافظة كخيار واضح.
- فتح رابط النتيجة في Chrome عبر ACTION_VIEW.
- لا نحقن نصوصًا داخل صفحة Chrome ولا نضغط أزرارًا نيابة عن المستخدم دون واجهة تكامل صريحة.

### إضافة Chrome اختيارية لاحقًا
إذا احتجنا التقاط النص المحدد من صفحة ويب مباشرة، يمكن بناء إضافة Chrome منفصلة تستخدم صلاحيات محدودة وموافقة المستخدم وترسل النص المحدد إلى التطبيق عبر آلية ربط صريحة. لا تُعد الإضافة شرطًا للنسخة الأولى، ولا تستخدم صلاحيات قراءة كل المواقع افتراضيًا.

## تسجيل دخول ChatGPT
- استخدام SIWC الرسمي عبر OAuth Authorization Code + PKCE في متصفح النظام أو Chrome Custom Tabs.
- استخدام redirect URI الموثق في تكامل SIWC، والتحقق من state وPKCE.
- لا تطلب كلمة مرور ChatGPT داخل التطبيق، ولا تقرأ Cookies أو ملفات Chrome.
- تخزين الرموز باستخدام تشفير مرتبط بـ Android Keystore، وعدم كتابتها في السجلات أو ملفات Git.
- التحقق من أهلية خطة الحساب وتوفر SIWC للحساب والتطبيق قبل عرض الاتصال كميزة جاهزة.
- استخدام واجهات SIWC الرسمية فقط؛ لا نعيد استخدام جلسة موقع chatgpt.com أو جلسة تطبيق ChatGPT.
- لا وصول تلقائي إلى سجل محادثات ChatGPT أو الذاكرة.
- موافقة صريحة قبل إرسال ملفات أو تشغيل مهام خلفية.
- لا API proxy عام، ولا مشاركة أو تجميع استحقاقات الاشتراك لمستخدمين آخرين.

## تدفق العمل الموحد
1. يشارك المستخدم رابطًا أو نصًا أو ملفًا من Chrome أو تطبيق آخر.
2. يعرض مركز التحكم معاينة المحتوى ومصدره ويطلب الموافقة على المعالجة.
3. يختار المستخدم محرك المعالجة: ChatGPT أو النموذج المحلي أو أدوات Linux.
4. يمكن لسير العمل أن يمرر ناتج محرك إلى محرك آخر، مع إظهار ما سيتم إرساله وموافقة المستخدم عند إرسال بيانات إلى السحابة.
5. تعمل أوامر Linux في مساحة عمل محددة، وتحتاج الأوامر الحساسة أو التي تغير أو تحذف ملفات إلى تأكيد.
6. يحفظ التطبيق النصوص والبيانات المنظمة والتقارير محليًا.
7. يعرض النتيجة ويتيح مشاركتها مجددًا إلى Chrome أو تطبيق آخر.

## مكونات Android المقترحة
- Kotlin + Jetpack Compose للواجهة.
- AndroidX Browser Custom Tabs وIntents لفتح Chrome والتكامل.
- Activity وIntent filters لاستقبال المشاركات.
- Storage Access Framework لاختيار الملفات والمجلدات.
- Android Keystore لحماية رموز SIWC.
- طبقة خدمة محلية للتواصل مع Termux على 127.0.0.1 مع رمز عشوائي وموافقة المستخدم.
- محول منفصل للنموذج المحلي ومحول SIWC لـ ChatGPT.
- لا تستخدم AccessibilityService كوسيلة تحكم عامة؛ لا يضاف إلا لوظيفة وصول حقيقية وبموافقة صريحة.

## ما هو موجود وما لم ينفذ بعد

الموجود في هذا الفرع: نموذج أولي لخادم Termux المحلي ونقاط فحص النموذج والمهام.

غير المنفذ بعد: تطبيق Android أصلي، استقبال وإرسال Intents فعليًا، تكامل SIWC، تخزين Keystore، واجهة اختيار المحرك، واختبارات على هاتف Android. هذا المستند مواصفات تنفيذ وليس ادعاءً بأن التكامل يعمل بالفعل.

## معايير القبول
- يفتح رابط HTTPS في Chrome المثبت أو المتصفح الافتراضي عند غياب Chrome.
- يستطيع التطبيق استقبال نص ورابط وملف من Android Sharesheet.
- لا يقرأ بيانات Chrome الخاصة أو ChatGPT cookies.
- يظهر بوضوح ما إذا كانت المهمة ستذهب إلى النموذج المحلي أو ChatGPT.
- لا يرسل ملفًا للسحابة دون اختيار وموافقة المستخدم.
- لا تُخزن رموز SIWC بنص صريح ولا تظهر في السجلات.
- يستطيع المستخدم مشاركة النتيجة إلى Chrome أو تطبيق آخر.
- يبقى النموذج المحلي والطرفية قابلين للعمل عند انقطاع الإنترنت.
